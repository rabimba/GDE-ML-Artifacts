Slide 1 / 14 Session Opening ⏱️ 00:00 – 00:35

Defeating the Prefix-Cache Penalty: KV-Aware Routing & Disaggregated Serving for Agent Fleets on GKE

[00:00 - 00:35] Kubernetes services were built around a simple assumption: HTTP requests are independent, pods are interchangeable, and round-robin spreads load evenly. When you run an autonomous SWE or SRE agent fleet behind a stateless Service, you spend most of your accelerator cycles recomputing identical prompt prefixes across replicas. And if you switch to naive longest-prefix sticky routing, parallel agent fan-out herds onto a single pod and makes P95 tail latency worse than round-robin. In this session, we will walk through why both failures happen and how we fix them using Gateway API Inference Extension and disaggregated TorchTPU serving on GKE.

Slide 4 / 14 Part 1: The Agent Tree Workload ⏱️ 01:20 – 02:30

Chatbots Are Lines. Agent Fleets Are Trees.

[01:20 - 02:30] Why do agent fleets break standard serving pools? Because a chatbot is a line, whereas an agent workflow is a tree. When an incident orchestrator triggers on an alert, it assembles a 20,480-token shared trunk—80 blocks of 256 tokens holding MCP tool schemas, repository structure, and alert state—and at millisecond zero spawns 8 parallel sub-agents. Each sub-agent pulls 8,192 tokens of pod logs and diffs before converging on a synthesis turn. Over the episode, 85.6% of tokens across those branches are shared prefix blocks.
Slide 5 / 14 Part 1: Fork-Storm Topology ⏱️ 02:30 – 03:20

Anatomy of an 8-Way Incident Orchestrator Fork-Storm

[02:30 - 03:20] Look at the token budget across a single orchestrator episode. Blocks 0 through 79 form the 20,480-token parent trunk. When the orchestrator forks 8 sub-agents simultaneously, all 8 child requests carry those exact 80 block hashes, followed by a 2-block role delta and a 32-block (8,192-token) log burst on Turn 2. Finally, the join turn reuses the original 80-block trunk.
Slide 6 / 14 Part 2: Two Routing Failure Modes ⏱️ 03:20 – 05:00

Failure Mode 1: Stateless K8s Round-Robin & Failure Mode 2: The Prefix-Herd Trap

[03:20 - 05:00] Behind a standard Kubernetes Service, round-robin scatters those 8 child branches across all replicas. Every replica misses on the parent trunk, recomputes 20,480 tokens of prefill, and stalls co-located decode streams past 133 milliseconds P99 ITL. The natural next step is enabling longest-prefix sticky routing. That triggers a second failure mode during parallel agent fan-out: the Prefix-Herd Trap. At fork time, all 8 sub-agents match 80 out of 80 parent blocks on Pod 0. A router that maximizes prefix match sends all 8 concurrent branches to Pod 0 while Pods 1 through 3 sit idle. Worse, as those 8 branches append 8,192-token log bursts on Pod 0, they exceed Pod 0's 360-block HBM capacity and LRU-evict the shared parent trunk right before the synthesis join turn.
Slide 7 / 14 Part 3: Co-Designing Routing & Disaggregation ⏱️ 05:00 – 06:15

Why KV-Aware Routing & Disaggregation Need Each Other

[05:00 - 06:15] This is why routing and disaggregation have to work together. KV-aware routing on an aggregated pool ties compute affinity to memory residency, herding forked branches onto whichever pod holds the parent trunk. Disaggregation without KV-aware fit routing still recomputes shared prefixes. When we combine them, Prefill pods compute the shared trunk once, pin evicted blocks in 48 GiB of host DRAM, compute only the branch delta, and stream KV blocks over gVNIC to whichever Decode pod has HBM headroom.
Slide 8 / 14 Part 3: Control Plane (FleetKV EPP) ⏱️ 06:15 – 07:30

Control Plane: Fit-Aware Tree Routing in GAIE ext_proc

[06:15 - 07:30] Here is the scoring function inside fleetkv-epp. Every vllm-torchtpu prefill pod publishes BlockStored and BlockRemoved events over ZeroMQ on port 5557 as 256-token blocks enter HBM or spill to host DRAM. When Envoy forwards a request over ext_proc, the router first checks the HBM Fit Gate: if admitting another branch plus our 24-block safety reserve would overflow the pod's free HBM blocks, it spills that branch to a peer pod instead of evicting the shared trunk. Second, notice our staged lease accounting: we release InFlightPrefillTokens as soon as ResponseHeaders arrive at TTFT, while holding the HBM block reservation until the SSE decode stream completes.
Copyable Command / Prompt
func ScoreEndpoint(pod *PodState, req *RouteInput) float64 {
    // 1. Hard HBM Fit Gate: spill to peer if branch horizon overflows HBM
    effectiveFree := pod.FreeHBMBlocks - pod.ReservedBlocks
    if effectiveFree < req.EstimatedBranchBlocks + SafetyReserveBlocks {
        return RejectOverflowSpillToPeer
    }
    // 2. Trade off ZMQ-indexed block hits against in-flight prefill queue
    savedMs   := float64(pod.MatchedHBMBlocks)*HBMBlockMs +
                 float64(pod.MatchedDRAMBlocks)*DRAMBlockMs
    queueWait := float64(pod.InFlightPrefillTokens) / PodTokPerMs
    return savedMs - queueWait
}
Slide 9 / 14 Part 3: Data Plane (vllm-torchtpu + HMA) ⏱️ 07:30 – 08:30

Data Plane: vllm-torchtpu + TPUConnectorHMA on GKE

[07:30 - 08:30] On the data plane, our DisaggregatedSet runs vllm-torchtpu on GKE Trillium ct6e-standard-4t node pools. Prefill pods mount a 64 GiB /dev/shm volume and allocate 48 GiB to TPUConnectorHMA as a Tier-2 host DRAM cache, keeping shared agent trunks warm even when active branch deltas cycle through HBM. Once a prefill pod computes the branch delta, it transfers the KV blocks asynchronously over an MTU-8896 gVNIC network to the Decode pod selected by fleetkv-epp. Let's switch to the live terminal and watch all three stages under load.

Slide 12 / 14 Part 6: Production GKE Invariants ⏱️ 12:30 – 13:30

Three Production Invariants (Audited in CI by Gate G2)

[12:30 - 13:30] Three operational invariants before you deploy this on GKE—all enforced by tests/test_g3_k8s_manifests.py in CI. First, set PYTHONHASHSEED="0" on every container; otherwise Python's per-process hash randomization causes block hash mismatches across workers. Second, set --block-size 256 on both vllm-torchtpu and fleetkv-epp so Pallas paged-attention kernels fit inside TPU v6e Scalar Memory. Third, use a Kubernetes Headless Service (clusterIP: None) filtered to llm-d.ai/role=prefill so the router subscribes to every prefill pod's ZMQ socket individually, and configure mtu: 8896 on your gVNIC VPC.
