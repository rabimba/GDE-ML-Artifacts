Slide 7 / 20 Module 1 • Interactive Developer Setup ⏱️ 00:16 – 00:20 (4m)

Developer Workflow: Colab MCP + Single-Chip PJRT Sharing

🎬 [STAGE DIRECTION]: Highlight the PJRT initialization order in the code box on the right—this is a critical practical tip for engineers. 🗣️ SAY VERBATIM: "Here is a critical engineering tip when combining `torch_tpu` and JAX Pallas on the same chip. Both PyTorch and JAX talk to the TPU through `libtpu` and PJRT. If I import `jax` before `torch_tpu` initializes its PJRT client, or if `TPU_VISIBLE_DEVICES` conflicts with `TPU_VISIBLE_CHIPS`, they fight over the `/dev/vfio` device lock. By popping `TPU_VISIBLE_DEVICES`, pinning `TPU_VISIBLE_CHIPS='0'`, and allocating one tensor on `torch.device('tpu:0')` followed by `torch.accelerator.synchronize()` before importing `jax`—which I packaged into `autokernel.init_tpu(chip=0)`—both frameworks share the chip cleanly!"
Copyable Command / Prompt
// 1. .opencode/opencode.jsonc
{
  "mcp": {
    "colab-mcp": {
      "type": "local",
      "command": ["uvx", "colab-mcp"]
    }
  }
}

# 2. Single-Chip PJRT Sharing (encapsulated in autokernel)
os.environ.pop("TPU_VISIBLE_DEVICES", None)
os.environ["TPU_VISIBLE_CHIPS"] = "0"
os.environ["TPU_CHIPS_PER_HOST_BOUNDS"] = "1,1,1"
import torch, torch_tpu
_ = torch.ones(1, device="tpu:0")  # Acquire PJRT first!
torch.accelerator.synchronize()
import jax  # Shares PJRT client with torch_tpu

With `autokernel`, I tile the batch dimension via `solve_tile_size(N)`, DMA each `(128, 896)` block into on-chip VMEM once, fuse the entire `float32` variance reduction and weight scaling inside VPU registers, and DMA the `bfloat16` output back once.
