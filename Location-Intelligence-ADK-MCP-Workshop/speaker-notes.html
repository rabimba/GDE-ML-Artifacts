Slide 11 / 38 Module 1 • Concepts ⏱️ 00:13 – 00:15 (2 min)

MCP: from N×M integrations to N+M

TIMING: 00:13 - 00:15 (2 mins) GOAL: The 'why' of MCP — the integration math. SAY THIS: "Before MCP, wiring an agent to a data source meant a bespoke adapter: read the API docs, hand-write a client, hand-write the tool schema, pray about auth. Three agents times three data sources is nine brittle adapters." "MCP flips that. It's an open protocol — Anthropic created it, and it's now industry-wide, with Google as a founding member of the Agentic AI Foundation. A server exposes its capabilities as standard 'tools'; any MCP client discovers and calls them. Write the server once, write the client once, and N-plus-M replaces N-times-M. People call it 'USB-C for AI' and the analogy is exact: one connector, any device." KEY VOCAB on this slide: Host = the app the user talks to (ADK web UI). Client = the connection inside the host. Server = the thing exposing tools (BigQuery, Maps).
Slide 12 / 38 Module 1 • Concepts ⏱️ 00:15 – 00:16 (1 min)

MCP anatomy: Host, Client, Server

TIMING: 00:15 - 00:16 (1 min) SAY THIS: "Three roles. The Host is the app you talk to — ADK's web UI. Inside it, a Client maintains one dedicated connection per server. The Server is where the tools live. And the transport is how bytes move: stdio for a server running as a subprocess on your laptop, or Streamable HTTP for a remote server." "Today both our servers are remote and Google-hosted, so it's Streamable HTTP with an auth header. That's why you don't install BigQuery or Maps SDKs at all — you saw the repo: no BigQuery client code, no Places client code. Just two URLs."

Slide 14 / 38 Module 1 • Concepts ⏱️ 00:18 – 00:19 (1 min)

BigQuery MCP server — the 6 tools

TIMING: 00:18 - 00:19 (1 min) SAY THIS: "What can the agent actually do in BigQuery? Six tools. It can list datasets, list tables, and read metadata — and then the two interesting ones: execute_sql runs arbitrary SQL, and execute_sql_readonly does the same with mutations blocked. Because it's full SQL, the agent can even call BigQuery's AI.FORECAST function — that's how it does the revenue projection you'll see later." "Here's the subtle part — watch get_table_info. When the agent needs to write SQL, it first asks the server for the table schema, and the server returns the column descriptions that the setup script wrote: 'foot_traffic_index — index of estimated foot traffic based on commercial density.' The agent uses that text to decide which column to query. So your schema documentation literally becomes part of the prompt. Good descriptions, smarter agent."

Maps Grounding Lite — the 5 tools

Slide 16 / 38 Module 1 • Concepts ⏱️ 00:20 – 00:21 (1 min)

Two servers, two auth patterns — tools.py

TIMING: 00:20 - 00:21 (1 min) SAY THIS: "Open tools.py and it's almost disappointingly simple — two functions, same pattern. Maps takes an API key in a header; the setup script created a restricted key that only works for the maps tools service. BigQuery is stricter: it's your enterprise data, so it wants OAuth. We pull a token from your Application Default Credentials and pass it as a Bearer header, plus x-goog-user-project so queries bill to your project." "Now the one operational gotcha of the whole day — star this. That OAuth token lives about 60 minutes, and ADK does not refresh it for you. If your agent suddenly starts failing late in the workshop, re-run gcloud auth application-default login. Write it down."
Copyable Command / Prompt
# --- Maps: API key ---
MCPToolset(connection_params=
  StreamableHTTPConnectionParams(
    url='https://mapstools.googleapis.com/mcp',
    headers={'X-Goog-Api-Key': maps_api_key}))

# --- BigQuery: OAuth bearer (from ADC) ---
creds, pid = google.auth.default(scopes=[BQ_SCOPE])
creds.refresh(Request())
MCPToolset(connection_params=
  StreamableHTTPConnectionParams(
    url='https://bigquery.googleapis.com/mcp',
    headers={'Authorization': f'Bearer {creds.token}',
             'x-goog-user-project': pid}))
